## Why other expensive tests remain

All six provider-agent real-D1 days remain. Their measured traces contain
distinct binding, result and write-state domains. Keeping only idle,
intermittent renewal and revoked access would lose permanent-error and
typed-expiry transitions. Paired client mutations confirmed that dropping typed
failure metadata or successful verification metadata loses behavior not covered
by the proposed smaller matrix. Smaller case counts alone are insufficient
evidence.

Both populated OLD-schema history sizes remain. The larger original rebuild
measures historical foreign-key amplification; the indexed correction meters
preparation, migration and restoration separately. Neither an empty migration
replay nor post-migration query tests substitute for this proof.

The capacity virtual day still executes all 1,440 attempts through the original
JSON CAS store and real WebCrypto. Every charge, read, write, compaction and
byte assertion retains its five-second deadline. Priority alone failed in normal
CI before browser startup, so the native integrity gate runs the 56 in-process
strict cases with one worker before admitting heavy flows. Its 49 Python cases
remain. The main phase runs the other 1,592 Vitest cases, and combined
accounting requires all 1,648 exactly once. Missing, stale, substituted, omitted
or duplicated proof fails. Standalone Vitest still runs the full inventory.

Small fixture and SHA-driver prototypes did not establish meaningful gains and
were rejected. The capacity-owner and runtime-graph tests and all production
source remain unchanged. A separate local-source Linux probe stopped at SSH
authentication before any remote command; it supplies no timing evidence. Source
checks may overlap wide work, while PDF isolation waits for source checks to
finish. Every flow still follows the isolated gate and must pass in the complete
receipt. Existing samples provide weighted host execution/steal measurements
without adding reads or changing sampling. The legacy busy peak includes steal;
flow CPU remains a lower bound. Complete normal CI remains the acceptance path
for this resource schedule.

The quieter gate exposed a cash fixture that relied on wall-clock review times
being different. With tied observations and tied review times, the existing
projection deliberately prefers a reported balance. A private fixed-clock
control reproduces that assertion failure. The fixture now sets Date explicitly
and advances the second review by 1 ms. The unreviewed account still retains its
reported amount, then becomes unknown after the later review. All assertions,
observations, inputs and real timeout remain. The original failed run did not
retain both timestamps, so their equality in that run is unconfirmed.

The quota-pause browser fixture also waits for accepted loaded states before
advancing virtual time. Request-entry counters alone did not establish that
responses had activated every poller. Holding initial responses for two seconds
reproduces the original three-expected, one-received assertion failure on both
projects. The readiness assertions pass the same control. All original pause
notices, request counts, activity events, timeout and 20-minute pause assertions
remain. Historical CI response ordering was not captured and remains
unconfirmed.

The partial-cash browser journey reuses the real collection response consumed by
the page after each save/reload, replacing three additional API-context reads.
Request capture starts before the action and rejects earlier in-flight requests.
All 18 original snapshot assertions remain. Five local paired runs reduce
collection reads from nine to six without an elapsed-time claim. Under a
controlled four-second response delay, the original mobile case expires while
the candidate retains its unchanged 30-second deadline. Historical CI latency
was not measured by that control.

Native source checks reuse typed ESLint's compiler programs instead of starting
separate compiler checks for the same contexts. Each required context still
produces complete pre-emit diagnostics, including sources ignored by ESLint.
Context discovery, options, roots and configuration errors remain enforced, as
do JavaScript lint errors and the zero-warning limit. Unsupported source types,
parsers/processors, project references, incremental/composite builds and
emission modes fail the combined command. Standalone lint and typecheck remain
available. The retained synthetic controls exercise compiler errors and missing
coverage rather than only checking the helper's structure. No new compiler,
persistent cache or receipt protocol is introduced.

Compiler regression fixtures share loaded modules in one owned child per case,
with a fresh compiler operation for each input. The operation clears parser and
project-service caches before and after checking. A retained same-path mutation
control catches the stale-source false acceptance observed without that reset.
All 34 original predicates and the three case identities remain, with real CLI
smokes. The parent retains each fixture's 20-second limit and aggregate one-MiB
output bound, rejects late responses and removes its exact child on failure or
close. This removes repeated Node startup without sharing compiler programs
between fixtures. Local component measurements do not establish whole-suite
Linux fit.

Real PDF isolation, production browser/document capture, current authentication,
quota denial, stale/unknown evidence, uncertain replay, concurrency and owned
cleanup boundaries remain mandatory. No timer is increased to accept a faster
looking result.

## Equivalence and measurement

The setup comparison checks SQL operations and bindings, complete application
state and measured host results. Generated identifiers are normalized only in
private comparison evidence. Separate runs of SQLite trigger clocks naturally
differ; only their documented clock columns are normalized. Client-supplied
financial dates are retained exactly. Uncontrolled rename read counters can vary
by one row; every original bound remains, and exact billing equality is not
claimed from those uncontrolled runs.

The controlled Wefunder comparison matches all 153 SQL operations and bindings
and all 137 application tables with 7,480 rows. No state or clock normalization
is needed for those controlled inputs. Every original measured host assertion
and SQL literal remains. Invalid setup commands return 400 without creating an
import.

Old and new migration postconditions are challenged with stored-row corruption,
extra/missing/changed schema, disabled immutable guards and a real foreign-key
violation. Browser controls challenge geometry, focus, unsaved drafts and a fast
search no-op. These are failure-detection checks, not screenshot updates.

Instrumented profiles diagnose the limiter and are excluded from timing samples.
Per-case work and concurrent flow durations are not added to claim elapsed time.
The final exact-revision CI receipt remains the end-to-end result; a local or
isolated gain does not establish tail reliability.
